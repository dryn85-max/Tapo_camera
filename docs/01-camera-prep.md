# 1. Подготовка камер Tapo C200

## 1.1. Первичная настройка (один раз, нужен аккаунт TP-Link)

Обойти это нельзя: камера с завода настраивается только через приложение
Tapo, а приложение требует TP-Link ID. Дальше облако не используется.

1. Установить приложение Tapo, добавить обе камеры в свой Wi-Fi.
2. Обновить прошивку камер до последней (Настройки камеры → Обновление
   прошивки). После отключения интернета обновлять будет нельзя.
3. Выключить ненужное: Настройки → Уведомления, Tapo Care (облачная
   запись), «Обнаружение» можно оставить, события движения приходят в ONVIF.
4. Создать **аккаунт камеры**: Настройки камеры → Расширенные настройки →
   Аккаунт камеры. Это отдельный логин/пароль именно для RTSP и ONVIF,
   он не совпадает с TP-Link ID. Пароль: только латиница и цифры, без
   спецсимволов, иначе часть NVR не может его передать в URL.
5. Записать MAC-адреса камер (Настройки камеры → Информация об устройстве).

## 1.2. Сеть в UniFi

1. **Статические IP**: UniFi Network → Client Devices → камера → Settings →
   Fixed IP. Например `192.168.1.50` и `192.168.1.51`.
2. Желательно отдельная VLAN для камер (IoT). Protect-консоль должна её
   видеть, а WS-Discovery (UDP 3702 multicast) работает только внутри одной
   L2-сети, поэтому либо консоль в той же VLAN, либо включить mDNS/multicast
   routing, либо добавлять камеру в Protect вручную по IP.
3. **Блокировка интернета для камер** (после п. 1.1):
   UniFi Network → Settings → Security → Traffic & Firewall Rules →
   создать правило: Source = группа «Tapo cameras» (два IP), Destination =
   Any (Internet), Action = Drop.
4. **Исключение для NTP.** Без интернета часы камеры со временем уйдут, а
   ONVIF-аутентификация (WS-UsernameToken) чувствительна ко времени: Protect
   начнёт получать «Authority failure». Два варианта:
   - разрешить камерам только UDP 123 наружу (правило Allow выше правила Drop);
   - или поднять NTP на самой консоли UniFi и сделать DNAT UDP 123 с камер
     на консоль.

## 1.3. Порты камеры

| Порт | Протокол | Назначение |
|------|----------|------------|
| 554/tcp | RTSP | `rtsp://user:pass@IP:554/stream1` (1080p) и `/stream2` (360p) |
| 2020/tcp | ONVIF | Device/Media service, Profile S |
| 443/tcp | HTTPS | собственный протокол Tapo (приложение, go2rtc `tapo://`) |
| 3702/udp | WS-Discovery | автообнаружение ONVIF |

Проверить всё сразу: `scripts/check-camera.sh 192.168.1.50 camuser 'campass'`.

## 1.4. Лимит одновременных потоков

Камера держит ограниченное число RTSP-сессий (по отчётам: около 2 на каждый
из двух потоков, суммарно до 4). Если потоки тянут одновременно Protect,
приложение Tapo, Frigate или Home Assistant, появляются чёрные экраны и
обрывы. Решение: один клиент забирает поток с камеры и раздаёт всем
остальным. Это и делает мост из [docs/03-bridge.md](03-bridge.md).
