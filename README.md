# Tapo C200 → UniFi Protect без облака Tapo

Комплект инструкций и конфигов, чтобы две камеры **TP-Link Tapo C200** работали
в сети Ubiquiti (UniFi Protect) локально: без постоянного участия аккаунта и
облака TP-Link, с записью, просмотром и событиями движения в Protect.

Новая прошивка **не пишется**. Три проверенных пути, от простого к сложному:

| Путь | Что нужно | Когда выбирать |
|------|-----------|----------------|
| [1. Нативный ONVIF](docs/02-native-onvif.md) | Только Protect 5.0.33+ | Всегда начинать с него |
| [2. Мост go2rtc + rtsp-to-onvif](docs/03-bridge.md) | Любой Linux-хост с Docker | Если путь 1 глючит, или видео нужно ещё и Frigate / Home Assistant |
| [3. Открытая прошивка Thingino](docs/04-thingino.md) | Пайка, ревизия C200 на Ingenic | Если хочется полностью избавиться от прошивки TP-Link. Для C200 V5 пока не рекомендуется, см. документ |

## Целевое железо

Консоль: **UniFi Dream Router 7 (UDR7)**, схема и расчёт хранилища в
[docs/00-hardware-udr7.md](docs/00-hardware-udr7.md).

Камеры: 
две Tapo C200(DE) **Ver 5.0** (ЕС, 2024, прошивка 1.5.7): Ingenic T23N, SC2336P, RTL8188FTV,
8 МБ flash, только Wi-Fi. Thingino этот вариант поддерживает, но на октябрь
2026 требует пайки и имеет открытый баг корневой ФС для 8 МБ сборки.

## Быстрый старт

1. [Подготовить камеры](docs/01-camera-prep.md): обновить прошивку, завести
   «аккаунт камеры», выдать статические IP, отрезать от интернета.
2. Проверить потоки скриптом:
   ```bash
   ./scripts/check-camera.sh 192.168.1.50 camuser 'campass'
   ```
3. Пройти [путь 1](docs/02-native-onvif.md). Если не адоптится или рвётся
   поток, поднять [мост](docs/03-bridge.md) из папки `bridge/`.

## Почему не своя прошивка

- ISP (обработка картинки с сенсора) и аппаратный H.264-кодек у всех чипов
  в C200 (Realtek RTS3903, Ingenic T23N/T31L) закрыты. Без вендорского SDK
  картинки не будет.
- Для Ingenic эта работа уже сделана проектом Thingino, он поддерживает C200
  на T23N и T31L. Для Realtek-ревизий открытой прошивки нет.
- Прошивка TP-Link и так отдаёт RTSP и ONVIF Profile S локально. Облако нужно
  один раз, при первичной настройке.

## Что не будет работать в Protect со сторонней камерой

- AI-детекции (человек, авто, лица, номера) без отдельного UniFi AI Port.
- Аудио: либо не пишется, либо транскодируется на консоли (зависит от версии).
- PTZ через Protect: официально не поддерживается для сторонних камер.
  Поворот камеры остаётся через приложение Tapo (локально) или ONVIF-клиент.

## Структура

```
docs/      пошаговые инструкции
bridge/    docker compose: go2rtc (ретранслятор RTSP) + rtsp-to-onvif (виртуальные ONVIF-камеры)
scripts/   проверка камеры: порты, ONVIF, ffprobe потоков
```
